# 予約ジョブのJavaScript実行設計

Issue: https://github.com/tetetratra/smart-speaker/issues/345

## 要件と対象範囲

予約のinstructionをscriptへ置き換える。
スケジュール、永続化、単発ジョブ削除は維持する。
互換性対応はせず、旧予約はデプロイ前に手作業で変換する。
JSから同期関数toolcall(name, args)を呼び、戻り値を扱えるようにする。
非同期ツールは受付結果のみ返し、最終結果は履歴へ記録する。
直接実行の呼び出し、結果、後続通知はRealtimeの接続や応答生成を開始しない。
remind(text)だけが既存の通知処理で応答を要求する。
通常会話からのツールと通知の動作は維持する。
履歴は起動中のみ保持し、未利用記録は会話終了でも失わない。
専用画面は追加せず、既存のautomation表示とツール履歴を利用する。

## 構成

予約サービスは時刻計算と保存、JS実行器はgojaによる実行、共通ツール実行器はHandler呼び出しと画面用履歴を担当する。
HandlerをRun(ctx, args)へ変更し、共有インスタンスのSetContextは廃止する。
Goのcontextには呼び出しごとの不変な実行情報を型付きキーで保持する。
共通実行器は既存と同様にエラーをJSONのerrorへ変換する。
通常会話のcall_id重複排除はtoolcallerに残す。
直接実行の履歴とremindは同じIngressへFIFOで送り、toolcallの記録より先にremindが処理されないようにする。
初期化は予約サービス、ツール登録、共通実行器、JS実行器、各ステージの順に完了してからHTTPとschedulerを起動する。
予約サービスの実行コールバックは起動前に完成したJS実行器を参照する。

## JS実行

実行ごとにgojaのRuntimeとrun_idを作る。
公開関数はtoolcallとremindのみで、Node APIやイベントループは導入しない。
引数と戻り値はJSONを介して変換し、既存ツールと同じ数値形式にする。
toolcallの未知のツール、引数不正、ツール失敗はerrorを含むオブジェクトで返し、JSは続行する。
JS例外、通知受付の失敗、タイムアウトはジョブ失敗として記録する。
remindは受付まで待ち、戻り値は持たない。
実行済みの操作や送信済み通知は後続失敗で取り消さない。
wait_for_userは会話制御なので直接実行対象外とする。
登録、更新、読み込みで構文検証し、script上限は32,768バイトとする。
実行は直列、同期ツールを含め30秒上限とし、既存の5秒送信期限を置き換える。
goja.Interruptに加え、同期HTTPにも実行contextの期限を渡す。
タイムアウト後の新しいツール実行を禁止する。
外部操作の取り消しや、contextを無視するGo関数の強制停止は保証しない。
非同期処理は受付時の情報をコピーしてアプリcontextで継続し、JS終了ではキャンセルしない。

## 通知context

bridgeのPOST /tasksに任意のcontext JSONオブジェクトを追加する。
本体はdelivery（history_only）、automation_id、run_id、call_idなどを設定する。
モデルのツール引数には公開せず、本体が実行情報から付与する。
Goではjson.RawMessage、TSではRecord<string, unknown>として保持する。
bridgeはオブジェクト型と16KiB上限のみ検証し、中身は解釈しない。
作業単位で保存し、完了、失敗、承認依頼の各イベントと再送にそのまま付ける。
本体はdeliveryなしを既存通常通知、history_onlyを履歴専用、その他のdeliveryを入力エラーとして扱う。
Web検索も同じ情報を後続結果へ引き継ぐ。
履歴専用では「口頭で知らせる」など通知用指示を除き、結果データとして整形する。
承認依頼も履歴と既存表示に残すだけにし、自動許可しない。既存期限で拒否する。
イベントIDは受付成功後だけ記録し、再送を重複排除する。
受付を直列化することで、失敗時の重複排除状態の巻き戻しを不要にする。

## 履歴の保持とRealtimeへの反映

外部記録は不変ID、role、source、text、呼び出し情報を持つ。
Realtimeは未利用ID集合と接続ごとの反映済みID集合を管理する。
記録受付では会話履歴と画面だけを更新し、接続、世代変更、応答要求は行わない。
未利用の外部記録はContextBuilderの要約対象から除外し、接続後の応答前にそのままmessageで渡す。
既利用の記録のみ通常の履歴snapshotと要約に含め、未利用記録の省略を防ぐ。
接続待ち中に追加された記録は次の応答前に追加する。
response.create直前に未反映の記録をmessageとして送信FIFOへ入れ、その応答へ含む未利用ID集合を固定する。
同epochのresponse.createdで固定したIDのみ利用済みにする。
要求後の新着記録、接続のみで未使用の記録、応答開始前の切断時の記録は未利用のまま残す。
会話終了のDrainは未利用IDを残して切り離す。
接続完了時はpendingWake、pendingTextより先に外部履歴を反映する。
結果はモデルが要求したfunction_call_outputを偽装せず、過去の記録データとして渡す。
通知記録で進行中の応答を中断しない。
ウェイクモード変更などツール固有の接続更新は既存動作を維持する。

## APIと画面

POST/PUT /api/jobsのinstructionをscriptへ置換し、構文不正は400とする。
GET、予約ツールの登録、更新、一覧もscriptに合わせる。
画面は指示入力を等幅のスクリプト入力へ変更し、既存エラー表示を流用する。
実行開始、終了、例外、タイムアウトはrun_id付きautomation記録としてtoolhistoryの既存inbound表示へ必ず残す。
ジョブ一覧から削除された単発予約も同じように記録する。
非同期受付と最終結果を区別し、script正常終了と最終処理成功を混同しない。

## 検証とリリース

同期戻り値、エラー、JS例外、時間制限、複数ジョブ、保存/再読み込みを検証する。
直接実行と後続通知が接続/response.createを起動しないことをテストする。
同一接続、再接続、接続待ち、会話終了、toolcall後のremindで履歴を取りこぼさないことを検証する。
通常会話の通知、bridge contextの早着/再送/未知キー、JS終了後の非同期完了も検証する。
bridgeを先に更新し、予約を手作業で変換してから本体を更新する。
マージとデプロイはこのPR作成作業には含めない。

## 設計レビュー反映

高性能モデルによる実装前レビューで、未利用外部記録を要約対象から除外すること、単発ジョブの実行履歴をジョブ保存とは独立させることを追加した。

追加レビューで、通知形式不正は400、一時的なIngress受付失敗は503としてbridge再送を維持する設計へ修正した。
同一event_idの受付は直列化し、受付失敗した処理を別の再送で成功扱いにしない。
gojaの構文検証はsource map読み込みを無効にしてparse/CompileASTを行い、実行時のeval等にも同じ設定を適用する。
JSは同期処理のみをサポートし、Promiseグローバルを無効化する。
未処理rejectionと実行結果に返った未完了Promiseは失敗として扱う。
ローカル変数内の未完了Promiseまで検出するAST走査やイベントループは作らない。

## 実装時の簡素化

未使用になったDelivery.InboundMessageは削除し、remindの通知文はRunnerへ集約する。
通知の表示は既存SourceとRoleで区別し、直接ツール結果の表示は共通実行器、非同期通知とジョブ状況の表示は既存inbound記録に任せる。

高性能モデルの実装レビューで、同期限定を明確にするためPromiseグローバルの無効化を追加した。

## 実装レビュー反映

高性能モデルのレビューで、遅着した履歴専用の承認依頼も記録すること、JSでcatchしても通知受付の失敗をジョブ失敗として残すことを修正した。
再送の重複排除は成功した受付だけを保持するルールにまとめ、失敗時の巻き戻し処理を削除した。
