# 呼びかけ必須モード

既定は呼びかけ不要です。必須モードでは**毎回の発話**に呼びかけを含める必要があります。直前に呼びかけても、次の発話の判定を省略する時間はありません。

## 音声の処理

不要モードは従来どおり音声をRealtimeへ送ります。必須モードは端末ごとにローカルで発話を区切り、ローカルSTT（faster-whisper、CPU int8）で認識します。認識信頼度と呼びかけの類似度の両方がしきい値以上の場合だけ、認識テキストをRealtimeへ送ります。呼びかけのない発話の音声・テキストはRealtimeや会話履歴へ渡しません。拒否した発話をアプリのファイルやログには残しません。

発話の区切りには音量（RMS 0.012以上）と800msの無音を使い、200msの直前音声を含めます。200ms未満の短い音声と、30秒を超える連続音声は無視します。認識は同時1件、待機最大2件・各45秒で、混雑・失敗・低信頼度では受け付けません。モード設定の変更や端末再接続をまたぐ認識結果は破棄します。必須・不要を切り替えるとRealtime接続を更新し、残った入力音声・VAD通知を失効させます。

呼びかけの既定は「スピーカー」。Unicodeの空白・句読点・大小文字・ひらがな／カタカナを正規化し、連続部分に対する編集距離から類似度（0〜1）を計算します。完全一致だけには限定しません。STT信頼度（0〜1）は認識した単語確率の平均で、**正しく認識した確率として校正された値ではありません**。各区間のavg_logprob・no_speech_probと単語probabilityもSTTのレスポンスに含みます。

## 設定

画面のチェックボックス、`get_wake_mode`・`set_wake_mode`ツールから切り替えます。`set_wake_mode`の引数は`required`（必須）と`word`（変更時のみ）です。UIでは信頼度の下限（既定0.55）と類似度の下限（既定0.8）も変更でき、直近の数値と判定を表示します。`GET /api/wake-mode`で取得、`PUT /api/wake-mode`で更新します。

```json
{"required":true,"word":"スピーカー","min_confidence":0.55,"min_similarity":0.8}
```

設定は`WAKE_MODE_STORE_PATH`（既定はメモリ保存ファイルと同じフォルダのwake-mode.json）へ保存します。認識中の音声や判定履歴は再起動で失われます。

Docker Composeに`local-stt`サービスを追加しています。ホストへのポート公開はなく、アプリから`http://local-stt:8000/transcribe`へ送ります。`LOCAL_STT_MODEL`（既定small）と`LOCAL_STT_THREADS`（既定4）で調整できます。初回起動ではモデルをダウンロードしてDockerボリュームへ保持し、その後の推論はローカルです。単独実行時のアプリ設定は`LOCAL_STT_ENDPOINT`（既定http://localhost:8000/transcribe）です。`GET /health`が成功するのはモデルの読み込み後です。

## 予約との組み合わせ

このPR単体では予約機能を含みません。[予約PR #290](https://github.com/tetetratra/smart-speaker/pull/290)も導入した後、自然言語の指示でモード切替を予約できます。予約からの内部指示はマイク入力ではないため、呼びかけの判定対象にはなりません。無音で実行する場合はspeak=falseで登録します。

| 用途 | cron（Asia/Tokyo） | 自然言語の指示 |
|---|---|---|
| 平日9時に必須 | 0 9 * * 1-5 | 呼びかけ必須モードをオンにして。読み上げ不要 |
| 平日20時に解除 | 0 20 * * 1-5 | 呼びかけ必須モードをオフにして。読み上げ不要 |
| 深夜0時に必須 | 0 0 * * * | 呼びかけ必須モードをオンにして。読み上げ不要 |
| 朝6時に解除 | 0 6 * * * | 呼びかけ必須モードをオフにして。読み上げ不要 |

予定は自動では登録しません。

## 精度と制限

音量で区切るため、雑音や連続した会議音声では認識の遅延や見逃しが生じます。STTの表記揺れ・同音語・会議内の呼びかけと似た単語による誤判定もあり、音響専用ウェイクワード検出器ほど低遅延・低負荷ではありません。モデル・言葉・しきい値は利用するマイクと環境の実音声で調整してください。

使用APIの根拠: [faster-whisper公式README](https://github.com/SYSTRAN/faster-whisper#usage)、[単語確率・区間指標の定義](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)。

## 検証

`go test ./...`、対象パッケージの`go test -race`、`python3 -m unittest discover -s services/local-stt`、フロントエンドのテスト・ビルド・型検査で検証します。
ローカルDocker（Linux aarch64、CPU・smallモデル・4スレッド）では、合成音声「スピーカー、今日の予定を教えてください。」を認識できました。STTのHTTP処理は約3.52秒、信頼度は約0.974でした。これは1件の合成音声の結果で、マイク・会議音声での誤反応率や遅延を保証するものではありません。
