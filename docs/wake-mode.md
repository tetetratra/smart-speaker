# 呼びかけ必須モード

既定は呼びかけ不要です。必須モードでは、発話を**呼びかけで始める**必要があります。呼びかけが通ると「会話中」になり、**最後のユーザー発話から1分間**は呼びかけなしで話せます。1分間ユーザーが話さなければ、次の発話からまた呼びかけが必要です。

会話中かどうかはメモリだけで持ち、ファイルには保存しません。再起動や設定の変更で会話中は終わります（必須モードのオン・オフの設定は保存したまま残ります）。

## 音声の処理

不要モードは従来どおり音声をRealtimeへ送ります。必須モードで会話中でないときは、端末ごとにローカルで発話を区切り、ローカルSTT（faster-whisper、CPU int8）で認識します。認識信頼度がしきい値以上で、呼びかけのパターンに一致した場合だけ、認識テキストをRealtimeへ送ります。呼びかけのない発話の音声・テキストはRealtimeや会話履歴へ渡しません。拒否した発話はアプリのファイルには残しません（調査用のログには残ります。後述）。

会話中は、不要モードと同じく音声をローカルSTTを通さずRealtimeへ送ります。会話中の時間は、Realtimeが発話の開始を検出するたびに数え直します。読み上げ中やツールの実行中も時間は進むため、長い返答の後は呼びかけが必要になることがあります。会話中の開始・終了ではRealtimeの接続を作り直さず、終了時にクラウド側の未確定の入力音声を捨てます。呼びかけの認識中（約3.5秒）に続けて話した発話は、呼びかけが通った後に結果が届けば、呼びかけなしでも受け付けます。

呼びかけだけの発話（例:「起きて」）も、ほかの発話と同じくRealtimeへ送ります。その応答にだけ「起きていることを普段の口調で一言だけ伝える」指示を付けるため、システムプロンプトの口調で「起きたよ」などと返事します。呼びかけの言葉は設定で変わるため、この指示はシステムプロンプトではなく応答ごとに渡します。

発話の区切りには音量（RMS 0.006以上）と800msの無音を使い、200msの直前音声を含めます。有声部分が60ms未満の短い音声と、30秒を超える連続音声は無視します。音量と最短の有声時間は、スマホのマイクで短い「起きて」が捨てられていた実測（最大RMS 0.02前後・有声60〜120ms）をもとに決めています。認識は同時1件、待機最大2件・各45秒で、混雑・失敗・低信頼度では受け付けません。モード設定の変更や端末再接続をまたぐ認識結果は破棄します。必須・不要を切り替えるとRealtime接続を更新し、残った入力音声・VAD通知を失効させます。

呼びかけは**言葉との類似度**で判定し、文頭付近だけを調べます。既定の言葉は「おきて」「起きて」「オッケー」の3つです。STTが漢字とかなのどちらで書き起こしても通るようにし、短い「起きて」をSTTが聞き違えやすい「オッケー」も含めています。そのため、文頭付近の「オッケー」にも反応します。

- 認識テキストから空白・句読点を除き、カタカナをひらがな、英字を小文字へそろえます。言葉も同じようにそろえます。
- 先頭から`max_prefix`文字以内（既定4文字）で始まる部分を、言葉の長さ±2文字の範囲で取り出し、編集距離から類似度（0〜1）を計算します。前置きの「ねえ」「えっと」などは、この文字数の中で許します。
- 類似度の最大値が`min_similarity`（既定0.65）以上なら通します。3文字の言葉なら、1文字違い（類似度0.67、例:「置きて」「起きで」）まで通ります。
- しきい値以上の部分がテキストの末尾まで届いていれば、呼びかけだけの発話とみなします。

STT信頼度（0〜1）は認識した単語確率の平均で、**正しく認識した確率として校正された値ではありません**。各区間のavg_logprob・no_speech_probと単語probabilityもSTTのレスポンスに含みます。

## 設定

必須モードのオン・オフは、画面のスイッチと`set_wake_mode`ツール（引数は`required`だけ）、`PUT /api/wake-mode`（`{"required":true}`）で切り替えます。`GET /api/wake-mode`と`get_wake_mode`ツールで、現在の設定を確認できます。

呼びかけの言葉と判定のしきい値は、**`config.yaml`で決める固定値**です。画面・ツール・APIからは変更できません。変えるときは、`config.yaml`を書き換えて再起動（本番は再デプロイ）します。

| `config.yaml`の項目 | 内容 | 既定値 |
|---|---|---|
| `wake.words` | 呼びかけの言葉（リスト） | `[おきて, 起きて, オッケー]` |
| `wake.max_prefix` | 呼びかけの前に許す文字数（0〜20） | `4` |
| `wake.min_confidence` | STT信頼度の下限（0より大きく1以下） | `0.55` |
| `wake.min_similarity` | 言葉との類似度の下限（0より大きく1以下） | `0.65` |

範囲外の値や、数値として読めない値を指定すると、サーバーは起動に失敗します。

`GET`の応答には、会話中かどうか（`awake`）と終了予定時刻（`awake_until`）、直近の判定（`last`。信頼度・類似度・言葉との一致・受理・呼びかけだけか）も含みます。

必須モードのオン・オフだけを`wake.store_path`（既定はメモリ保存ファイルと同じフォルダのwake-mode.json）へ保存します。以前の保存内容に言葉やしきい値が含まれていても無視します。認識中の音声、判定履歴、会話中の状態は再起動で失われます。

Docker Composeに`local-stt`サービスを追加しています。ホストへのポート公開はなく、アプリから`http://local-stt:8000/transcribe`へ送ります。`LOCAL_STT_MODEL`（既定small）と`LOCAL_STT_THREADS`（既定4）で調整できます。初回起動ではモデルをダウンロードしてDockerボリュームへ保持し、その後の推論はローカルです。接続先は`config.yaml`の`wake.local_stt_endpoint`（既定はCompose内の`http://local-stt:8000/transcribe`）で、Composeを使わずに単独実行する場合は`http://localhost:8000/transcribe`などを指定します。`GET /health`が成功するのはモデルの読み込み後です。

## 予約との組み合わせ

このPR単体では予約機能を含みません。[予約PR #290](https://github.com/tetetratra/smart-speaker/pull/290)も導入した後、自然言語の指示でモード切替を予約できます。予約からの内部指示はマイク入力ではないため、呼びかけの判定対象にはなりません。無音で実行する場合はspeak=falseで登録します。

| 用途 | cron（Asia/Tokyo） | 自然言語の指示 |
|---|---|---|
| 平日9時に必須 | 0 9 * * 1-5 | 呼びかけ必須モードをオンにして。読み上げ不要 |
| 平日20時に解除 | 0 20 * * 1-5 | 呼びかけ必須モードをオフにして。読み上げ不要 |
| 深夜0時に必須 | 0 0 * * * | 呼びかけ必須モードをオンにして。読み上げ不要 |
| 朝6時に解除 | 0 6 * * * | 呼びかけ必須モードをオフにして。読み上げ不要 |

予定は自動では登録しません。

## 調査用のログ

呼びかけが反応しない原因を調べるため、必須モード中はサーバーのログ（`docker compose logs server`）へ`wakegate:`で始まる行を出します。

- 5秒ごとのマイクの最大音量（RMS）と、発話とみなすしきい値（0.006）
- 発話を区切ってSTTへ送ったこと（長さ・有声部分の長さ・最大音量）、または短すぎる・待ち行列が満杯で捨てたこと
- STTの待ち時間と処理時間、エラー
- 判定結果（書き起こしたテキスト・信頼度・類似度・受理したか）

**呼びかけのない発話も、書き起こしたテキストがログに残ります。** 必須モード中に周囲で話した内容が本番サーバーのディスクに残るため、原因を特定した後はテキストの出力を外す想定です。

## 精度と制限

音量で区切るため、雑音や連続した会議音声では認識の遅延や見逃しが生じます。STTの表記揺れ・同音語による見逃しや、文頭近くに呼びかけの言葉を含む発話（例:「早く起きてね」）での誤反応もあり、音響専用ウェイクワード検出器ほど低遅延・低負荷ではありません。モデル・言葉・しきい値は利用するマイクと環境の実音声で調整してください。

使用APIの根拠: [faster-whisper公式README](https://github.com/SYSTRAN/faster-whisper#usage)、[単語確率・区間指標の定義](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)。

## 検証

`go test ./...`、対象パッケージの`go test -race`、`python3 -m unittest discover -s services/local-stt`、フロントエンドのテスト・ビルド・型検査で検証します。
以前の呼びかけ「スピーカー」での計測では、ローカルDocker（Linux aarch64、CPU・smallモデル・4スレッド）で合成音声「スピーカー、今日の予定を教えてください。」を認識できました。STTのHTTP処理は約3.52秒、信頼度は約0.974でした。これは1件の合成音声の結果で、マイク・会議音声での誤反応率や遅延を保証するものではありません。
